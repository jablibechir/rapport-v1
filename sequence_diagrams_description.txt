----------------------------------------------------------------
HOW TO READ THIS GUIDE
----------------------------------------------------------------
Each diagram has:
  - PARTICIPANTS  : the vertical lifelines to draw (left → right)
  - MESSAGES      : numbered arrows between participants
    → solid arrow  = call / request
    --> dashed arrow = return / response
  - ALT / OPT blocks : draw a box with a dashed border labeled
    "alt" (for if/else) or "opt" (for optional)
----------------------------------------------------------------


================================================================
DIAGRAM 1 — REGISTER
================================================================

PARTICIPANTS (left to right):
  1. Visitor          (actor stick figure)
  2. Frontend         (React App)
  3. Backend          (Spring Boot API)
  4. Database         (cylinder icon)
  5. Email Service    (component box)

MESSAGES:

  1.  Visitor      →  Frontend      : Fill in registration form
                                      (firstName, lastName, email, password)

  2.  Visitor      →  Frontend      : Click "Register" button

  3.  Frontend     →  Backend       : POST /api/auth/register
                                      { firstName, lastName, email, password }

  ---- [ alt block: "Email already exists" ] ----
    4a. Backend    →  Database      : SELECT user WHERE email = ?
    5a. Database   --> Backend      : User found
    6a. Backend    --> Frontend     : 409 Conflict – "Email already registered"
    7a. Frontend   --> Visitor      : Show error message
  ---- [ else: "Email not registered" ] ----
    4b. Backend    →  Database      : SELECT user WHERE email = ?
    5b. Database   --> Backend      : No user found
    6b. Backend    →  Database      : INSERT new User
                                      (status = PENDING, role = CANDIDATE)
    7b. Database   --> Backend      : User saved (userId)
    8b. Backend    →  Database      : INSERT VerificationToken
                                      (token, userId, expiresAt = now + 24h)
    9b. Database   --> Backend      : Token saved
   10b. Backend    →  Email Service : Send verification email
                                      (to: email, link: /activate?token=...)
   11b. Email Service --> Backend   : Email sent OK
   12b. Backend    --> Frontend     : 201 Created – "Check your email"
   13b. Frontend   --> Visitor      : Show success message
  ---- [ end alt ] ----

  --- ACTIVATION STEP (separate interaction) ---

  14. Visitor      →  Frontend      : Click activation link in email

  15. Frontend     →  Backend       : GET /api/auth/activate?token=xxxxx

  ---- [ alt block: "Token valid" ] ----
   16a. Backend   →  Database       : SELECT VerificationToken WHERE token = ?
   17a. Database  --> Backend       : Token found, not expired
   18a. Backend   →  Database       : UPDATE User SET status = ACTIVE
   19a. Database  --> Backend       : Updated OK
   20a. Backend   --> Frontend      : 200 OK – "Account activated"
   21a. Frontend  --> Visitor       : Show "Account confirmed, you can sign in"
  ---- [ else: "Token expired or invalid" ] ----
   16b. Backend   --> Frontend      : 400 Bad Request – "Invalid or expired token"
   17b. Frontend  --> Visitor       : Show error + "Resend email" button
  ---- [ end alt ] ----

DIAGRAM 2 — SIGN IN
================================================================

PARTICIPANTS (left to right):
  1. User             (actor — Candidate / HR Officer / Manager)
  2. Frontend         (React App)
  3. Backend          (Spring Boot API)
  4. Database         (cylinder icon)

MESSAGES:

  1.  User         →  Frontend      : Enter email and password

  2.  User         →  Frontend      : Click "Sign In" button

  3.  Frontend     →  Backend       : POST /api/auth/login
                                      { email, password }

  4.  Backend      →  Database      : SELECT user WHERE email = ?

  5.  Database     --> Backend      : Return user record

  ---- [ alt block: "User not found" ] ----
    6a. Backend   --> Frontend      : 401 Unauthorized – "Invalid credentials"
    7a. Frontend  --> User          : Show "Incorrect email or password"
  ---- [ else: "User found" ] ----

    ---- [ alt block: "Wrong password" ] ----
      6b. Backend  → (internal)     : Compare password hash
      7b. Backend  --> Frontend     : 401 Unauthorized – "Invalid credentials"
      8b. Frontend --> User         : Show "Incorrect email or password"
    ---- [ else: "Password correct" ] ----

      ---- [ alt block: "Account not activated" ] ----
        6c. Backend  --> Frontend   : 403 Forbidden – "Account not activated"
        7c. Frontend --> User       : Show "Please verify your email first"
      ---- [ else: "Account suspended" ] ----
        6d. Backend  --> Frontend   : 403 Forbidden – "Account suspended"
        7d. Frontend --> User       : Show "Your account has been suspended"
      ---- [ else: "Account active" ] ----
        6e. Backend  → (internal)   : Generate JWT token (userId, role, exp)
        7e. Backend  --> Frontend   : 200 OK – { token, role, userId }
        8e. Frontend → (internal)   : Store JWT in localStorage/cookie
        9e. Frontend --> User       : Redirect to role-specific dashboard
                                      (Candidate / HR Officer / Manager)
      ---- [ end alt ] ----
    ---- [ end alt ] ----
  ---- [ end alt ] ----

DIAGRAM 3 — MANAGE USER ACCOUNT
================================================================

PARTICIPANTS (left to right):
  1. HR Officer       (actor stick figure)
  2. Frontend         (React App — Admin Interface)
  3. Backend          (Spring Boot API)
  4. Database         (cylinder icon)

MESSAGES:

  --- Load user list ---

  1.  HR Officer   →  Frontend      : Navigate to User Management page

  2.  Frontend     →  Backend       : GET /api/admin/users
                                      (Authorization: Bearer <JWT>)

  3.  Backend      →  Database      : SELECT all users

  4.  Database     --> Backend      : Return list of users

  5.  Backend      --> Frontend     : 200 OK – [ userList ]

  6.  Frontend     --> HR Officer   : Display user list

  --- Choose action ---

  ---- [ alt block: "Create new user" ] ----
    7a. HR Officer  →  Frontend     : Click "Create User" and fill form
                                      (name, email, role)
    8a. Frontend    →  Backend      : POST /api/admin/users
                                      { name, email, role }
    9a. Backend     →  Database     : Check if email exists
   10a. Database    --> Backend     : Not found
   11a. Backend     →  Database     : INSERT new User (status = ACTIVE)
   12a. Database    --> Backend     : Saved OK
   13a. Backend     --> Frontend    : 201 Created – { userId }
   14a. Frontend    --> HR Officer  : Show "User created successfully"

  ---- [ else: "Update existing user" ] ----
    7b. HR Officer  →  Frontend     : Select user → click "Edit"
    8b. HR Officer  →  Frontend     : Modify fields (name, email, etc.)
    9b. Frontend    →  Backend      : PUT /api/admin/users/{id}
                                      { updated fields }
   10b. Backend     →  Database     : UPDATE user WHERE id = ?
   11b. Database    --> Backend     : Updated OK
   12b. Backend     --> Frontend    : 200 OK – { updatedUser }
   13b. Frontend    --> HR Officer  : Show "User updated successfully"

  ---- [ else: "Deactivate user" ] ----
    7c. HR Officer  →  Frontend     : Select user → click "Deactivate"
    8c. Frontend    →  Backend      : PATCH /api/admin/users/{id}/deactivate
    9c. Backend     →  Database     : Check: is this the last active admin?
   10c. Database    --> Backend     : Not the last admin
   11c. Backend     →  Database     : UPDATE user SET status = INACTIVE
   12c. Database    --> Backend     : Updated OK
   13c. Backend     --> Frontend    : 200 OK
   14c. Frontend    --> HR Officer  : Show "User deactivated"
  ---- [ end alt ] ----

DIAGRAM 4 — MANAGE PERMISSION (ROLE ASSIGNMENT)
================================================================

PARTICIPANTS (left to right):
  1. HR Officer       (actor stick figure)
  2. Frontend         (React App — Admin Interface)
  3. Backend          (Spring Boot API)
  4. Database         (cylinder icon)

MESSAGES:

  --- Load user list ---

  1.  HR Officer   →  Frontend      : Navigate to User Management page

  2.  Frontend     →  Backend       : GET /api/admin/users
                                      (Authorization: Bearer <JWT>)

  3.  Backend      →  Database      : SELECT all users

  4.  Database     --> Backend      : Return user list

  5.  Backend      --> Frontend     : 200 OK – [ userList ]

  6.  Frontend     --> HR Officer   : Display users with their current roles

  --- Role assignment ---

  7.  HR Officer   →  Frontend      : Select a user from the list

  8.  Frontend     →  Backend       : GET /api/admin/users/{id}

  9.  Backend      →  Database      : SELECT user WHERE id = ?

  10. Database     --> Backend      : Return user details (including current role)

  11. Backend      --> Frontend     : 200 OK – { user }

  12. Frontend     --> HR Officer   : Display user profile + current role

  13. HR Officer   →  Frontend      : Select new role from dropdown
                                      (CANDIDATE / HR_OFFICER / MANAGER)

  14. HR Officer   →  Frontend      : Click "Save Role"

  15. Frontend     →  Backend       : PATCH /api/admin/users/{id}/role
                                      { newRole: "MANAGER" }

  ---- [ alt block: "Same role already assigned" ] ----
   16a. Backend   --> Frontend      : 400 Bad Request – "Role already assigned"
   17a. Frontend  --> HR Officer    : Show "This user already has this role"

  ---- [ else: "Would remove last administrator" ] ----
   16b. Backend   →  Database       : COUNT users WHERE role = HR_OFFICER
   17b. Database  --> Backend       : count = 1 (only one admin left)
   18b. Backend   --> Frontend      : 403 Forbidden – "Cannot remove last admin"
   19b. Frontend  --> HR Officer    : Show warning message

  ---- [ else: "Role change valid" ] ----
   16c. Backend   →  Database       : UPDATE user SET role = ? WHERE id = ?
   17c. Database  --> Backend       : Updated OK
   18c. Backend   --> Frontend      : 200 OK – { user with new role }
   19c. Frontend  --> HR Officer    : Show "Role updated successfully"
                                      Refresh user list
  ---- [ end alt ] ----


================================================================
NOTES FOR DRAWING
================================================================

LIFELINES  : draw a vertical dashed line under each participant box
ACTIVATION : draw a thin rectangle on a lifeline while it is processing
ARROWS     :
   →  solid arrow head   = synchronous message (request / call)
   --> open arrow head   = return / response message
ALT BLOCK  : large rectangle with dashed top dividing lines
             label each section with the guard condition in [ ]
OPT BLOCK  : like alt but labeled "opt" — only one branch

COLORS (optional, for clarity):
  Actor box      → white
  Frontend box   → light blue
  Backend box    → light green
  Database box   → light yellow
  Email Service  → light orange
